XINGJI · ONE-TIME SETUP

Token 一次配置，以后永不登录

生成一次，粘贴一次。之后所有更新都是「双击 deploy.bat → 等它跑完」，不用 git、不用输账号密码、不用打开 GitHub 网页。

1 生成一个 Token（约 60 秒，只做这一次）

  1. 打开 github.com/settings/tokens/new（需要登录 GitHub 网页一次，仅此一次）。
  2. Note 随便填，例如 行迹部署；Expiration 建议选 No expiration 或 90 天。
  3. 勾权限，见下面这两条，其余都不用勾：
✅ repo —— 读写仓库文件
✅ workflow —— 上传 .github/workflows/pages.yml，少了它一定会被 GitHub 拒绝

用 fine-grained token 也可以：给这个仓库 Contents: read/write、Workflows: read/write、Pages: read/write 三项即可。

  1. 拉到最底点 Generate token，复制那串 ghp_...（只显示一次）。

2 部署

  1. 把压缩包全部文件解压到一个空文件夹，index.html 与 deploy.bat 在同一层。
  2. 双击 deploy.bat，粘贴 Token（输入不显示），回车。
  3. 其余全自动：校验身份 → 没有就建仓库 xingji-studio → 一次提交推完 → Pages 设为 GitHub Actions → 触发部署 → 打印网址。
完事。等 1–3 分钟打开脚本给你的 https://用户名.github.io/xingji-studio/，收藏它。

3 以后更新 / 换仓库 / 不想每次粘贴

  1. 改完城市数据再上线：后台导出 cities.full.js / plan-config.js 覆盖到 data/，再双击一次 deploy.bat。脚本只上传真正变化的文件，没变化就不提交。
  2. 不想每次粘贴：把 Token 单独存成同目录的 token.txt（纯文本一行）。它已写进 .gitignore，不会被上传。或者设环境变量 GITHUB_TOKEN。
  3. 换仓库名：设 GITHUB_REPO=用户名/别的名字，或命令行跑 python deploy.py --repo 用户名/别的名字，或写进同目录 repo.txt。想用 https://用户名.github.io/ 根地址，仓库名填 用户名/用户名.github.io，脚本会自动按根地址输出网址。
  4. 想先看看会传什么：python deploy.py --dry-run，不联网、不读 Token。
  5. 站点也要提供单文件预览版下载：python deploy.py --include-single（约 9 MB，默认跳过，本地双击用不着上传）。
Token 安全：它等同于你的仓库写权限，别发聊天、别贴截图、别提交进仓库。脚本只在内存与请求头里用它，所有报错文案都会把 Token 打码；万一误提交，立刻到 GitHub 的 Token 页点 Revoke 重新生成。网络受限时脚本会明确提示，可设 HTTPS_PROXY 或用 --api-base 指向可达的桥。

脚本不安装任何依赖（Python 3.8+ 标准库），不修改你的 git 配置，不写注册表。deploy.bat 与 deploy.py 也会随站点一起上传，换电脑时从站点就能取回；本机凭据 token.txt / repo.txt 永远不会上传。
